# Порівняльний звіт: Fat vs Slim Docker Images

## 1. Параметри образів
| Метрика            | Fat Image (Dockerfile.fat) | Slim Image (Dockerfile.slim) |
|--------------------|---------------------------|------------------------------|
| Розмір (Size)      | 1.72 GB                   | 755 MB                       |
| Кількість шарів    | ~8-10                     | ~5                           |
| Базовий образ      | python:3.9                | python:3.9-slim              |

## 2. Аналіз "Fat" образу
"Важкий" образ має кілька критичних недоліків для MLOps:
* [cite_start]**Зайві пакети:** Містить системні залежності, компілятори та кеш `pip`, які потрібні лише під час збірки, а не під час роботи моделі[cite: 52, 120, 122].
* [cite_start]**Обсяг:** 1.72 ГБ — це занадто багато для швидкого розгортання в хмарі, що збільшує час завантаження (pull time) та витрати на сховище[cite: 120, 122].
* [cite_start]**Безпека:** Наявність зайвих інструментів (пакетних менеджерів, оболонок) збільшує ризики вразливостей[cite: 52].

## 3. Переваги "Slim" образу
Використання multi-stage build дозволило:
* [cite_start]Відокремити середовище збірки від середовища виконання[cite: 41, 111].
* [cite_start]Залишити лише скомпільовані бібліотеки, код `inference.py` та модель `model.pt`[cite: 43, 111].
* [cite_start]Суттєво зменшити кількість шарів у фінальному образі[cite: 116].

## 4. Подальша оптимізація
Для ще більшого зменшення розміру та покращення безпеки рекомендується:
* [cite_start]**Використання Distroless:** Образи без операційної системи (тільки додаток та його runtime), що робить їх максимально легкими та безпечними[cite: 124].
* [cite_start]**torchscript-lite:** Використання полегшеної версії рантайму PyTorch для inference[cite: 125].
* [cite_start]**Зменшення залежностей:** Використання версії `torch-cpu`, якщо не планується запуск на GPU, що може зекономити ще кількасот мегабайт[cite: 123, 124].
